# A-MCP Software Requirements Specification

## Purpose and Authority

This SRS translates the [A-MCP PRD](./prd.md) into implementable and verifiable contracts for the accepted overall normal-suite boundary. Initial Vona scaffold/configuration and application integration now exist under separately approved bounded increments recorded in the [phase-20 index](./evidence/phase-20/index.md); that source is not endpoint-readiness or ATP proof. It owns the MCP transport boundary, OAuth resource-server validation, instance binding, tool catalog and metadata, executor adaptation, authorization, privacy, rate limiting, audit, and operational behavior. The PRD owns product outcomes and scope; the [PDP/WBS](./pdp-wbs.md) owns delivery sequencing; the [test plan](./test-plan.md) owns executable `ATP-MCP-*` scenarios and evidence.

```text
PRD requirement -> SRS contract -> PDP/WBS task -> ATP scenario -> observed evidence
```

Unless explicitly marked as an observed current-source fact, this document defines a target contract, not implemented source. ADR 0001 accepts the revised `cabloy-mcp` normal-suite naming and overall first-increment boundary, including no new MCP-owned persistence; DEC-MCP-01 also accepts the initial scaffold manifests, discovery/generated registration, and configuration ownership. ADR 0001 preserves the original default-off/literal-`true` application-opt-in acceptance history and records its explicit 2026-10-17 user-directed bounded supersession: module-owned `enabled: app.meta.env.CABLOY_MCP_ENABLED !== 'false'`, default enabled, only literal `false` disables, without a standard application MCP `enabled` environment mapping. Generic framework application override precedence remains supported; this changes no OAuth/host/registry/policy fail-closed or readiness gate. The planning directory is `repo-specs/cabloy-mcp/`; existing `*-MCP-*` IDs and relative links remain unchanged. Initial suite/module source now exists as recorded in the phase-20 index. DEC-MCP-02 selects the transport protocol and SDK versions in ADR 0002 (design only); target-module compatibility and implementation-specific source remain unverified. DEC-MCP-03's bounded OAuth design is accepted, and ADR 0009 selects the integrated `a-auth` logical AS, `zhennann`'s implementation/operations responsibility, one AS-owned database-backed authority with code consumption/token activation in the same atomic commit, and Zova presentation of the AS-controlled per-request browser grant flow for bounded design. The first AS implementation target is SQLite via `better-sqlite3` on Vona's existing primary datasource; this is not an observed deployment or atomicity proof. Concrete issuer/resource configuration, AS schema/service and SQLite transition/migration proof, Zova site/admission and browser/session/CSRF implementation, host binding, registry, and policy remain gated; DEC-MCP-04 through DEC-MCP-08 are proposed.

## System Context

The proposed server sits between an external MCP client and existing Vona HTTP controller operations:

```text
External AI application
        │ MCP Streamable HTTP + OAuth bearer token
        ▼
MCP transport / protocol boundary
        │ request validation, host-instance binding, OAuth resource validation
        ▼
MCP catalog + authorization + fixed operation registry
        │ server-owned adaptation; no arbitrary route or header forwarding
        ▼
Fresh Vona request context + Passport mapping
        │ innerAccess: false
        ▼
bean.executor.performAction(...) / existing controller guards and AOP
        ▼
Existing domain service, Model, resource scope, transaction, and audit owners
```

The MCP layer is an adapter and policy boundary. It does not become the owner of domain persistence, account identity, tenant lifecycle, resource CRUD semantics, or controller business rules.

Trim the supplied name, then require 1–100 ASCII characters matching `[A-Za-z0-9_-]`, preserving case. The canonical identifier is exactly `mcp:custom:<name>`: input `test` produces `mcp:custom:test`, without a random suffix. The trimmed name must be unique within its owner and active instance; different users may safely use the same name and identifier. Personal CRUD cannot read or mutate another owner's/instance's presets; derive user identity from authenticated context, not body/query. Preserve original requested scope separately from effective approved scope. Consent selects exactly one all/read/custom value; compute effective tools as a subset of both original request and current registered client ceiling, never a union or silent promotion. Return actual effective scope at code exchange and refresh. Authenticated canonical definition resolution must bind owner and instance and require the stored identifier to equal the name-derived identifier; reject old random/noncanonical identifiers. Prelogin scope validation remains syntax-only and does not resolve personal definitions. No compatibility fallback, identifier migration or reset is introduced. Do not expose presets in public discovery/DCR or make registration a user grant.

Refresh inherits or narrows the issued effective tool ceiling and cannot gain tools by rereading an edited preset. A rename changes the canonical identifier. Rename, tool-set edit or deletion atomically revokes all code/access/refresh authority linked through either the old effective scope or the old requested scope, including grants narrowed from that requested custom scope; description-only edits do not revoke. Serialize or conditionally fence preset revisions and consent/code/token/refresh linkage so a rename or other revoking change racing issuance either invalidates the resulting linkage or prevents issuance; no stale valid credential escapes. Keep `mcp-auth` `fileVersion: 1`, folding persistence into the v1 creation path with ordinary metadata-owned lookup indexes, no business UNIQUE constraint, v2 migration, automatic existing-v1 replay or reset. The delivered refresh profile and ADR 0010 supersede incompatible original no-refresh/owner apparatus below only within this bounded slice; unrelated blocked parent and deployment gates remain. Traceability: `PRD-MCP-IDENTITY-01`, `PRD-MCP-IDENTITY-03`, `WBS-MCP-20-05`, `ATP-MCP-AUTH-03`, `ATP-MCP-INSTANCE-01`.

## Dispatch and Context Contracts

### SRS-MCP-DISPATCH-01: Fixed executor adaptation

Approved delete contribution (2026-10-30): use the [seventh-tool supplement](#approved-student-delete-seventh-tool-extension-2026-10-30)'s fixed registered DELETE with exactly `{ params: { id }, innerAccess: false }`, ordinary RBAC/current instance and shared service root admission before any cascade. The pre-read is not atomic; no lock/transaction/rollback/retry guarantee. Traceability: `WBS-MCP-40-01`, `ATP-MCP-CALL-01`, `ATP-MCP-CALL-02`, `ATP-MCP-INSTANCE-01`.

Traceability: `PRD-MCP-ACCESS-03`, `PRD-MCP-SAFETY-01`, `WBS-MCP-40-01`, `ATP-MCP-CALL-01`, `ATP-MCP-CALL-02`.

For each registry entry, the adapter maps MCP arguments to the known controller path/method/body/query/params shape and invokes the existing executor path with `innerAccess: false` **on that action call**, not merely on an outer context. It must preserve the selected controller guard/AOP chain and must not use trusted inner access. The server owns all executor options, including method, URL, headers, body, instance, auth context, and middleware behavior. For the current bounded mapper, bind to the registered `ContextRoute.routePathRaw`, not a recomposed/prefixed URL, and retain the authenticated request's ordinary business authority. [ADR 0007 (proposed)](./decisions/0007-mcp-context-passport-executor.md) retains the broader production identity/context and router-only-gap design; its historical unapproved-factory/action assumption does not undo the separately approved dev/test mapper.

The inspected executor directly runs router middleware, treats **only status 200** as success, unwraps a `code: 0` Cabloy response to `data`, and does not perform an HTTP JSON serialization round-trip. OpenAPI's default response schema is a wrapped 200 shape; it does not itself prove the runtime/serialized shape or redact extra fields. A supported tool must review the actual unwrapped 200 result and account for guards attached to router middleware versus any system-only middleware; 201/202/204, framework/custom responses, or security controls outside that path need a separate approved adapter or stay disabled. MCP admission must explicitly cover required OAuth, approved instance activation, transport-origin and request-size controls that the inner router cannot rerun; the executor's prepopulated body does not pass through the raw-body parser's HTTP limits. Never unwrap a domain value a second time just because it has a `code` field. A rejected post-execution shape cannot be assumed to undo a committed business effect.

### SRS-MCP-DISPATCH-02: Input and output binding

Approved delete contribution (2026-10-30): the [seventh-tool supplement](#approved-student-delete-seventh-tool-extension-2026-10-30) retains flat ID/string-or-number/nonempty-string validation, strict undeclared-control rejection and existing primitive-null output as equivalent `{ result: null }` channels. Null is completion only, including absent roots, not existence/count/complete-cascade/read-back proof; invalid output fails safely without raw fallback or replay. Traceability: `WBS-MCP-40-01`, `ATP-MCP-CALL-01`, `ATP-MCP-CONTRACT-01`.

Traceability: `PRD-MCP-ACCESS-03`, `PRD-MCP-CONTRACT-01`, `WBS-MCP-40-01`, `ATP-MCP-CALL-01`, `ATP-MCP-CONTRACT-01`.

The binding layer validates JSON arguments against the registry schema, applies only declared path/query/body mappings, rejects unknown or dangerous fields according to the DTO contract, and enforces request size/depth/string limits. It must never interpret an argument as a URL, method, host, cookie, authorization header, tenant selector, executor onion, or arbitrary state patch. The bounded mapper uses flat single-object-location input, declared multi-location groups, wrapped scalar/array bodies and strict empty arguments, reusing original Action runtime validators and rejecting empty path segments.

Outputs are converted from the executor's actual unwrapped value into a separately reviewed MCP field allowlist and runtime-validated JSON result; DTO/OpenAPI schema and the opt-in Vona serializer alone do not strip every undeclared field. JSON object/array/scalar/null representations must preserve the approved business result semantics without exposing internal envelope details unless that envelope is part of the declared tool contract. If a reviewed `outputSchema` is published, `structuredContent` conforms; any JSON text compatibility block is generated only from the same minimized value. An unexpected or unsafe result fails without raw-value fallback. In the bounded mapper, objects are direct structured content; arrays/scalars use `{ result: value }`, including declared scalar null, and text represents the same structured object. Apply `output.pick` to runtime fields and reachable schema closure. Undefined or missing object/null yields safe `Resource not found`; authorization, Action or output-validation failure yields `Action failed`.

### SRS-MCP-DISPATCH-03: Server-controlled execution options

Approved delete contribution (2026-10-30): reject caller body/route/method/tenant/instance/Passport/executor/confirmation controls before dispatch under the [seventh-tool supplement](#approved-student-delete-seventh-tool-extension-2026-10-30). Timeout/output/delivery failure can follow partial destructive effects and permits no automatic replay or rollback claim. Traceability: `WBS-MCP-40-01`, `ATP-MCP-CALL-02`.

Traceability: `PRD-MCP-SAFETY-01`, `WBS-MCP-40-01`, `ATP-MCP-CALL-02`.

The adapter fixes `innerAccess: false` on each executor action and builds a new options object without spreading caller values. It controls `onions`, headers, authentication propagation, instance name, deadline policy, and executor state. It must reject caller-supplied `Authorization`, cookie, forwarding, host/origin, instance, proxy, trace, protocol-control headers, query token keys, and executor controls rather than letting them select credentials or instance. It must not expose `options.onions`, `extraData.state`, `authToken`, or equivalent executor internals to tool arguments. The current executor has no generic abort/deadline/idempotency option; a transport timeout is not proof of cancellation. Validate sensitive-argument/result redaction in existing route/AOP logging and JWT diagnostics, not just MCP logging.

### SRS-MCP-DISPATCH-04: Fresh request context and Passport isolation

Traceability: `PRD-MCP-SAFETY-02`, `WBS-MCP-40-02`, `ATP-MCP-CALL-03`.

Each MCP tool call establishes a request-owned context with an explicit, trusted, non-null instance (an approved empty-string default instance is distinct from the `null` no-instance/system mode) whose Passport is constructed from the validated OAuth subject and bound instance before guarded dispatch. Check that the instance exists, is enabled and is ready; executor instance lookup alone is not HTTP `initInstance()` admission. The implementation must not rely on a nested executor call to replace an existing Passport: current executor/context delegation can share `state`, and an existing anonymous or authenticated Passport may prevent a new token from being checked. Project only the current instance-local, active mapped identity through the approved Passport adapter, not an external bearer through `authToken`, unreviewed `extraData.state`, or local `signin()`/JWT issuance. The inner action may inherit the authenticated state only from this _same_ per-call context; the action's route guards must compute their own current RBAC decision. The context factory must demonstrate an independent datasource and transaction ownership boundary, not merely a new Koa context, because compatible database/transaction ALS stores may be reused.

Concurrent MCP calls for different subjects or instances must not share mutable state, request headers, Passport, tool arguments, audit context, or authorization results. Any intentionally shared cache is immutable or keyed by all security-relevant dimensions and cannot carry caller identity. Real HTTP tests separately prove the trusted ingress path that router-only executor tests cannot cover.

### SRS-MCP-DISPATCH-05: Transaction and side-effect boundary

Traceability: `PRD-MCP-SAFETY-01`, `PRD-MCP-SAFETY-03`, `WBS-MCP-40-02`, `ATP-MCP-CALL-03`.

The MCP adapter does not create a new transaction around every operation by default. The existing controller/service owns transaction semantics, including `@Core.transaction(...)` where required; its default `REQUIRED` joins an ambient datasource transaction without upgrading isolation. A database commit, post-commit callback, `ctx.commit()` completion callback, external effect, response filtering, and client delivery are distinct boundaries: failure after an effect may leave its outcome uncertain to the client. The adapter must define bounded execution, timeout, cancellation, retry, response and protected outcome behavior without treating disconnect/deadline as automatic rollback or replaying non-idempotent business effects. Existing executor options have no generic signal, deadline, or idempotency key; do not detach work with a fire-and-forget `Promise.race` or treat `runInBackground` as durable recovery. Automatic MCP retry is prohibited; any domain retry/idempotency contract must be separately reviewed as replay-safe, including post-commit callback failure and duplicate client submission. If bounded, truthful completion or recovery cannot be demonstrated, leave the affected tool disabled. Destructive/irreversible calls require an explicit reviewed policy and must not be exposed solely because the route is guarded.

## Approved Student Lookup Retirement (2026-11-04)

The approved retirement of `training_student_lookup` supersedes earlier requirements to retain that Student action/tool or use its literal-substring, three-field, dedicated-page-bound contract for name discovery. Nine pre-retirement Student tools become eight: select/group/aggregate/view/summary reads and create/update/delete writes. Use select's existing LIKE name filter (`%` and `_` retain wildcard meaning, without literal escaping), choose a matching `list` row's returned `id`, then call summary or view only with independent student-view authority. Select returns complete serialized rows, including masked mobile; neither lookup's ID/name/level-only minimization nor its dedicated page bounds carries over. Existing select pagination applies. Summary remains exactly `id`, `name`, `level`, `levelTitle`, `descriptionLength` and `summaryText`.

See the [retirement index](./README.md#approved-student-lookup-retirement-2026-11-04) and [legacy select guidance](../../repo-docs/backend/mcp-controller-tools.md#example-complete-student-select). Token lookup and unrelated authorization contracts are unaffected. Earlier approvals/evidence remain historical and unchanged; this contract supersession does not itself supply runtime proof or acceptance closure.
