This document does not itself accept the separately decided DEC-MCP-02/03 designs or DEC-MCP-04 through DEC-MCP-08, select an audit sink or operator, configure production limits, authorize source/provider work, enable any tool, execute an ATP, or approve release. ## Current-source observations and limits

The inspected executor calls router middleware directly and prepopulates an in-process body; it does not rerun the HTTP raw-body parser, system middleware or an HTTP response serialization round trip. Its options do not expose a general operation deadline, `AbortSignal`, idempotency key or durable call status. A transport response close and a timer cannot prove cancellation, transaction rollback or non-execution. The MCP transport will therefore need its own admission limits, outcome classification and release-field projection, including for calls that fail **after** a business commit. These are source observations, not implemented MCP controls.

The inspected global [rate-limit interceptor](../../../vona/src/suite-vendor/a-vona/modules/a-ratelimit/src/bean/interceptor.rateLimit.ts) is disabled by default. When enabled, its [Redis service](../../../vona/src/suite-vendor/a-vona/modules/a-ratelimit/src/service/rateLimit.ts) counts fixed-window requests by instance, route, policy and a hash of IP and/or local Passport identity. This is neither an OAuth-client/tool/aggregate-instance quota nor an in-flight cap. Router guards run before route interceptors, so its declared position before body parsing is not a preauthentication perimeter. Its enforce-mode Redis error returns 503, but the limiter client does not establish a bounded Redis-outage wait. The [body request interceptor](../../../vona/src/suite-vendor/a-vona/modules/a-body/src/bean/interceptor.bodyReq.ts) defaults to a 20 MB raw JSON allowance; it does not bound JSON structure, SDK parsing or prepopulated executor bodies. These are **source defaults, not approved MCP limits**.

The inspected [HTTP log middleware](../../../vona/src/suite-vendor/a-vona/modules/a-logger/src/bean/middlewareSystem.httpLog.ts) serializes request headers/URL and response headers; the executor's [method AOP](../../../vona/src/suite-vendor/a-vona/modules/a-logger/src/bean/aopMethod.log.ts) can serialize arguments/results at debug level and errors at error level; [JWT diagnostics](../../../vona/src/suite-vendor/a-vona/modules/a-jwt/src/service/jwtClient.ts) print tokens at debug level. The [error filter](../../../vona/src/suite-vendor/a-vona/modules/a-error/src/bean/filter.error.ts) may include raw messages in logs and JSON, especially in development; [trace middleware](../../../vona/src/suite-vendor/a-vona/modules/a-telemetry/src/bean/middlewareSystem.trace.ts) permits a bounded caller-supplied request ID and records original exceptions. Neither level-filtering nor a redacted MCP emitter alone proves these independent sinks safe. Domain-specific payment/commerce audits and optional sampled telemetry are not a general protected MCP audit facility; checked-in local observability configuration is not proof of deployment retention/delivery. Initial `cabloy-mcp` scaffold/configuration and application integration now exist under separately approved bounded increments in the [phase-20 index](../evidence/phase-20/index.md); this qualifies the earlier no-module observation, not the absence of an approved MCP audit event, enforced MCP quota, tested cancellation or approved sink. Initial source does not establish operational readiness or ATP proof.

## Proposed decision

### Limit stages and ownership

Admit only the approved HTTPS endpoint when DEC-MCP-01 configuration, DEC-MCP-02 transport, DEC-MCP-03 resource token and DEC-MCP-04 trusted endpoint/instance configuration are complete. Define an **ordered, layered** budget so malformed or unauthenticated traffic cannot force expensive JWT/JWKS, parsing, catalog, data access or logging work:

1. At trusted ingress and on public resource metadata, limit connections, header/URL bytes, request-body bytes, parse time and request rate using an ingress-owned untrusted-source key. Never treat a caller-supplied `Host`, forwarded IP, query instance, raw token or unauthenticated client identifier as a trusted quota key. Proxy/CDN policies may supplement but cannot silently replace the reviewed in-process boundary; verify real HTTP ordering.
2. Before business dispatch, apply bounded JSON depth, collection sizes, string/argument bytes, batch/message count and schema complexity, plus catalog/list sizes and pagination work. Size checks must cover the native SDK/transport parser and the already-populated executor body; the ordinary Vona body parser's default does not secure that path. Reject unsupported/oversized requests **before** action invocation without logging raw payloads. Public metadata and `tools/list` also need response and CPU/work budgets.
3. After trusted host binding and OAuth mapping, key rate and simultaneous in-flight work by approved instance, local subject, OAuth client/grant identity and tool/policy revision, with a global/worker cap as a backstop. Use server-derived opaque/pseudonymous keys; isolate each authorized subject/instance and avoid disclosing another subject's bucket. Apply per-tool weighted costs where reads, writes and external calls differ. Avoid treating a request IP or a cached `tools/list` as current subject authority.
4. Enforce bounded response bytes and approved JSON shape **after** DEC-MCP-06 field filtering but before sending any JSON or SSE bytes. A result that is too large after domain execution is an execution-started failure/uncertain-delivery class, not proof of rollback. Never fall back to a truncated, unfiltered or raw executor result.

Set reviewed numeric limits and window/burst semantics for request headers, body and parse work, JSON depth/collection/arguments, list entries/pages, response bytes, queued/admitted/in-flight work, rate per key, execution and cleanup deadlines, and audit/telemetry resource use. Distinguish global, instance, client, subject and tool ceilings and decide which gate runs before identity is known. Specify atomic quota backend/worker and restart behavior under the actual deployment topology; an in-memory per-worker counter is **not** a fleet-wide cap. Decide what happens when that backend is unavailable or limits/configuration are absent before exposing tools; do not silently permit unbounded work. Rate-limit decisions must be measured at the request layer and cannot be inferred solely from a route interceptor whose key/route context may differ from the MCP ingress. The exact numeric values and mechanisms are `TODO(confirm)` and are not supplied by this draft.

A deadline bounds admission and accounting but is not an executor cancellation primitive. Stop admitting new work after deadline/disconnect, do not send more bytes on an unwritable response, and release an in-flight slot only after the owned operation actually settles or an independently designed durable recovery owner takes over. Do not `Promise.race` into untracked detached work, free a slot at socket close while a mutation is still active, or retry an uncertain operation. If active work cannot be bounded and truthfully accounted for, leave that tool disabled under DEC-MCP-07. Client-facing limit and timeout classes must follow the accepted protocol; return nondiagnostic errors without per-subject quota disclosure.

### Audit, telemetry and outcome accounting

Define a **protected audit event contract**, separate from sampled diagnostic logs/traces/metrics. Cover endpoint activation/disablement and tool-policy/config changes, protected discovery/list and call admission/denial, dispatch start, guarded authorization, completion, limit/rate denials, post-commit/filter failures, disconnect/deadline, and an outcome-uncertain or recovery transition. For each event retain only a documented event type, server-generated correlation identifier, time, approved instance and tool/policy/registry revision, pseudonymous local subject/client identifiers when known, risk/confirmation decision, safe denial/outcome class and bounded timing/limit dimension. Before authentication, record only a nonidentifying ingress class and approved instance if safely bound. Missing identity is a distinct state, not an anonymous local Passport. No event claims that client delivery proves business success or that a timeout proves rollback.

Use a reviewed existing platform sink or an explicitly selected external protected sink without adding an MCP-owned audit table. The chosen operator must define access control, encryption, event integrity, delivery/acknowledgment and availability, buffer/drop/failure handling, deduplication/correlation across workers, retention/deletion, export, incident response and how configuration/policy changes are audited. A logging call or an unawaited queue push is not proof of durable retention. If a required audit event cannot be delivered or the sink is unavailable, deny **new state-changing dispatch** before business effects; do not pretend a post-effect audit failure undid a transaction. Whether read/list requests also fail closed, and the exact behavior during partial sink outages, need explicit operator acceptance. Without an approved sink, retention and failure policy, keep the production MCP surface disabled. This decision assumes no new MCP resource-module-owned persistence; ADR 0009's AS-owned shared-state planning allowance is separate and does not approve an MCP audit table or any particular AS store/schema. Any proposed audit store needs a separate authority change, and any persisted field/schema edit requires the owning module's `vonaModule.fileVersion` decision first.

Telemetry supplements audit but cannot replace it. Generate an MCP operation correlation identifier independently of optional tracing and client-supplied HTTP request IDs, JSON-RPC IDs and business idempotency keys. Preserve it across the external HTTP context, OAuth/host checks, nested route execution, late settlement and response delivery: existing trace middleware may accept a caller-supplied `x-request-id`, while executor telemetry state does not automatically copy that request ID. Correlation cannot be treated as identity or authorization. Use bounded low-cardinality metric labels (no raw token, subject, client, row ID or arbitrary tool argument), avoid exporting raw request/response bodies as span attributes, and explicitly review tracing sampling and log retention. Define how operators distinguish rejected-before-dispatch, attempted/denied-by-controller, completed-and-delivered, execution-started/result-unknown and separately observed settled-but-not-delivered outcomes, while preserving what is genuinely unknowable.

### Disclosure and redaction boundary

Default to a **field allowlist**, not a regex pass over serialized arbitrary payloads. Never retain raw Authorization/cookie values, tokens or JWKS/key material, passwords/hashes, OAuth claims, tool arguments, full DTO/model results, private links, unreviewed user identifiers or full exception causes in audit, logs, metrics, traces, response errors or durable ATP evidence. Sanitize free-form error/tool descriptions and bound length and cardinality; do not leak a row's existence through limit or denial detail. Review the SDK's protocol/error logging, Vona dedicated HTTP file logs and error renderer, nested executor AOP argument/result **and error-level** logs, local JWT debug path, ORM interpolated-SQL diagnostics, rate limiter, domain/platform audit sinks, trace-exception export, reverse proxy and external collection/retention separately. A generic logger level does not prove a dedicated HTTP file transport is disabled; a truncated SQL value is not redaction. A transport-only redaction filter is insufficient when the route's logger or a provider library logs before filtering.

Use correlation IDs and either non-reversible per-sink pseudonyms or a documented keyed hash with approved key custodian/rotation policy if cross-event linkage is necessary; a bare hash of a low-entropy subject ID is not a privacy control. Redacted evidence retains synthetic labels, configuration and registry fingerprints and exact procedures/results, never live secrets or production identities. Keep operational events protected and independently assessable without requiring their raw payloads to be sent to an AI client. The exact allowlist/scrubber placement and sink access/retention remain `TODO(confirm)`.

### Configuration, absence and disablement

Under ADR 0001's 2026-10-17 user-directed bounded supersession, module `src/config/config.ts` owns `enabled: app.meta.env.CABLOY_MCP_ENABLED !== 'false'`: enabled by default, disabled only by the literal string `false`. Unset, empty, `true` and other non-`false` values leave the module flag enabled. There is no standard application MCP `enabled` environment mapping; generic framework application overrides remain supported and merge after module defaults. Flag enablement is not endpoint, tool or operational readiness. Validate mandatory limit/audit/telemetry configuration at startup and on refresh as part of a single approved policy revision, independently of basic module discovery. A missing/malformed required ceiling, unsafe sink, stale policy fingerprint, unsupported exporter/logging mode or quota-backend failure must not silently enable an unbounded tool. Where a required control becomes unavailable at runtime, disable new work under a reviewed atomic policy, account for already-started work until settlement, and continue to permit ordinary non-MCP HTTP behavior. Per-tool policy disablement must not make an authorized operation callable by another MCP name. Operational names/config keys are future integration choices, not existing environment settings; do not store secret values in this specification.

## Alternatives rejected or deferred

- **Rely on Vona's default body parser and route rate interceptor alone:** rejected; a native MCP transport and nested executor have different parsing/middleware and quota ownership.
- **Unlimited work with a response timeout or `Promise.race`:** rejected; already-started work may continue after the response closes or the deadline fires.
- **Per-process counters as a global deployment limit:** rejected unless the approved deployment topology actually has one worker and tests prove that invariant; multi-worker policy requires coordinated or conservatively partitioned capacity.
- **Raw request/response, token or claims logging followed by best-effort redaction:** rejected because data may already have crossed a sink boundary and optional downstream AOP debug logging is independent of MCP response filtering.
- **Treat sampled traces/console logs as a durable audit trail:** rejected; sampling, delivery and retention are separate requirements.
- **Write an MCP resource-module-owned audit/consent/limit table to make the first increment operational:** deferred; it conflicts with the accepted no-new-MCP-resource-module-persistence boundary. ADR 0009 permits planning AS-owned authorization state only, not an MCP audit/consent/limit table.

## Acceptance and execution gates

Before accepting `DEC-MCP-08`, `zhennann` must separately review and record:

1. the numeric/configuration matrix for each ingress, parser, argument/list, result, rate, worker/global/instance/client/subject/tool, and execution/cleanup ceiling, plus key derivation, preauth abuse controls, quota-backend availability, bounded outage wait and worker restart behavior; demonstrate that the disabled-by-default fixed-window route limiter, raw-body parser and ORM page-size defaults are not mistaken for MCP limits;
2. exact transport/route ordering with the approved SDK, parser, Vona interceptors and guarded executor; deadline/disconnect accounting coordinated with DEC-MCP-02/07, without claiming that timeout cancels a business effect;
3. a named **operational sink owner** (not just the accountable decision owner), audit event fields/classes, protected sink delivery guarantees, outage policy, storage location, encryption/access/retention/deletion/export, and configuration/policy-change evidence—without new MCP schema;
4. per-sink source-to-release field map, pseudonym/correlation policy independent of optional tracing, existing HTTP file/AOP error and args/JWT/ORM SQL/SDK/proxy/trace-exception/exporter logging review (including debug and nonproduction errors), metrics cardinality and evidence redaction; refusal to enable a tool when its downstream logging cannot be made safe;
5. targeted and real HTTP `ATP-MCP-OPS-01/02`, `ATP-MCP-TRANSPORT-01`, `ATP-MCP-CALL-01/03` proof for limit/denial ordering, cross-subject quota isolation, multi-worker/outage behavior, post-commit uncertainty, source-to-sink redaction and no ordinary-HTTP regression; retain revision, environment, procedures and redacted artifacts only after a separately approved execution dossier.

This is a proposed planning contract, not a selection of production numbers, audit retention or live controls. It does not itself create an MCP endpoint, telemetry pipeline, audit event, verified ATP, or release approval.

### Numeric proposal and enforcement

All sizes are bytes unless stated otherwise; KiB means 1024 bytes. A limit is checked before crossing its release boundary, not merely asserted after sending oversized output. Fixed bounded denials must themselves satisfy output limits.

| Dimension               | Proposed fixture ceiling                                                                                    | Enforcement and failure                                                                                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Connections             | 4 accepted loopback sockets, no keep-alive reuse                                                            | Own socket set; refuse excess without executor work; close each response/connection; no unbounded connection queue under fixture control                                                                                             |
| Ingress headers/target  | 8 KiB complete header block; 32 raw header fields; 2 KiB per field value; 256-byte target                   | Native `maxHeaderSize`, plus explicit raw-field/target checks; do not mistake Node's header-count truncation for rejection; fixed `431`/`414` or native early parser rejection                                                       |
| Header receive          | 2 seconds from socket acceptance                                                                            | Native timeout settings plus owned receive watchdog; account for Node timeout-check granularity; close partial/slow ingress with no executor entry                                                                                   |
| Active requests         | 2 reservations, zero waiting queue                                                                          | Reserve before body reading/executor; third request gets fixed `429`; reservation remains until real settlement, not socket close; pre-executor failures release only their owned reader/cleanup reservation                         |
| Body                    | 16 KiB actual bytes; identity encoding only; 2-second receive deadline                                      | Validate declared length and count actual chunks through one reader; no unbounded drain; fixed `413`/`408`; stop/close input on failure                                                                                              |
| JSON structure          | Depth 8 (root = 1), 256 total value nodes, 32 keys per object, 32 array entries, 2 KiB UTF-8 per string/key | Byte and fatal UTF-8 checks first, then parse and bounded iterative traversal; top level must be one request object, not a batch/response; fixed bounded protocol failure before SDK dispatch                                        |
| Response headers        | 8 KiB total, 32 fields, 2 KiB per value                                                                     | Verify all SDK header/commit paths before native submission; no arbitrary error/header reflection                                                                                                                                    |
| JSON payload            | 16 KiB                                                                                                      | Bounded serialization/buffering before commitment, including SDK-generated errors; excess precommit output becomes fixed failure, never truncation                                                                                   |
| Request-scoped SSE      | 8 frames, 2 KiB per frame, 16 KiB total wire body including framing, 2 KiB maximum incomplete-frame buffer  | Incremental validation and accounting before forwarding; no unbounded frame/task queue; cancel and close on postcommit overflow, do not append an error envelope                                                                     |
| Backpressure            | 1-second drain wait, at most one bounded pending frame/write                                                | Preserve `write() === false`; wait for drain or abort/error/terminal; expire into cancellation, not a second writer                                                                                                                  |
| Execution               | 5 seconds from reservation, including body receipt                                                          | Deadline requests cancellation; fixed precommit `504` or postcommit stream termination; continue truthful settlement accounting                                                                                                      |
| Cleanup                 | 1 second after cancellation/normal work settlement initiates cleanup                                        | Watchdog marks failure and closes admission if exceeded; not permission to detach work or release a live slot                                                                                                                        |
| Owned HTTP case/suite   | 15 seconds per case, 120 seconds for the selected suite, measured after app startup                         | Cooperative shutdown first, then 1-second hard-exit grace for this dedicated test child under ADR 0007; nonzero failure/retained resources are not successful cleanup; startup/runner deadlines remain separate and must be recorded |
| Retained fixture events | 512 events/run, 512 UTF-8 bytes/event, 256 KiB total                                                        | Build from the allowlist below, no raw spool; excess marks qualification failure, not silent truncation or successful evidence                                                                                                       |

Boundary tests cover exactly-at/over values, duplicate/framing ambiguity, slow input, output backpressure, pre-/post-header failure and cleanup-held concurrency. Synthetic strings remain nonsecret and bounded. If a valid selected-profile discovery fixture exceeds these proposed test ceilings, report the mismatch for one concrete numerical disposition; do not silently increase limits or call it a protocol defect.

### Source-to-sink scope

The raw router fixture deliberately omits the full system chain. Therefore ordinary HTTP header/URL logging, trace exception capture and method override/instance middleware are **not exercised or qualified**. No production logging config, global console/prototype or origin/proxy setting is patched. The fixture does not call JWT, ORM, business action/AOP or external provider paths; admission rejects credential headers. Managed app startup still uses the normal isolated-resource preparation path, so its output is retained only through the existing sanitization/manual-review procedure, not claimed to be covered by the MCP event schema.

Allowed fixture events contain only a server-assigned case alias (maximum 64 ASCII characters), fixed outcome enum, HTTP status, numeric bytes/frames/counts/duration, monotonic event sequence and settlement/disposal/slot booleans. Never record request header/body/URL/query, protocol params, arbitrary RPC ID/name, context/Passport, raw Error/message/stack/cause, token or customer data. Assertion diagnostics must compare bounded projections rather than dump raw requests or SDK objects. SDK internal protocol logging, console/error paths and error payloads must be inspected in the selected installed versions before the listener opens. If those sinks cannot be disabled or replaced by a supported fixed-field boundary within the approved scope, fail this candidate; process-global console monkeypatching or path sanitization is not a substitute.

The same response gate covers normal JSON/SSE and SDK-generated errors; finite output bytes alone do not establish nondisclosure. Retain only synthetic case outcomes, counters, event ordering, source hashes and sanitized command/exit chronology. No production protected-audit durability, multi-worker quota, subject/client isolation, trace exporter safety or retention guarantee follows from this per-invocation fixture. `ATP-MCP-OPS-01/02`, the full transport ATP and the parent WBS remain open.
