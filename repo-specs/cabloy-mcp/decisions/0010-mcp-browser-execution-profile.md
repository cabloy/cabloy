# ADR 0010: Bounded MCP Browser Authorization Execution Profile

## Status and precedence

**Accepted for the user-approved bounded implementation on 2026-10-23; not runtime evidence or release qualification.** This records the corrected connected flow contributing to `WBS-MCP-20-04` and `WBS-MCP-20-02`. It supersedes incompatible, unimplemented directions in [ADR 0003](./0003-mcp-oauth-resource-server.md), [ADR 0009](./0009-mcp-as-state-boundary.md) and their legacy SRS/WBS/ATP/dossier references **only for this increment**. Former preparation handoffs and superseded mechanism gates are historical, not instructions to restart planning. Compatible OAuth, tenant, authorization, privacy, lifecycle and acceptance requirements remain in force; no WBS/ATP completion or production exposure is implied.

## Decision

- **Owners:** backend `cabloy-mcp/modules/mcp-auth` owns AS state, decisions, issuance and current lookup/revocation; backend `cabloy-mcp` consumes it one-way as RS. Dev/test-only `mcp-test` retains `/mcp` and existing read-only tools. Zova `cabloy-mcp/modules/cabloy-mcp` owns consent presentation. Existing identity/login owners remain unchanged. New `mcp-auth` starts at `fileVersion: 1`; do not modify existing `a-auth` schema/version or infer reset approval.
- **Navigation:** `/mcp/auth` validates trusted instance, client, exact registered redirect, resource, scope and S256 before any client-directed error redirect. Copy enabled SSR Sites for the current instance/host; choose minimum `publicPath.length`, preserving order for ties. Do not change specificity-first routing, inspect page availability or add a capability check. Use the Site helper for fixed `/cabloy/mcp/consent?request=<opaque-reference>`; include the shared route in selectable Basic/Commerce Web/Admin flavors without bypassing Site-role admission.
- **Existing identity only:** reuse protected-page admission, SSR/browser Passport cookie, normal login and exact internal `returnTo`, never the OAuth callback as login continuation. Reuse the existing `home-passport` cookie → generated API Authorization header → backend `GuardPassport` chain, including integrated-SSR header handoff and account/activation checks. The locator is not identity or approval. Add **no extra cookie, holder, identity bridge, session system, CSRF bootstrap, resume endpoint or callback-state store**.
- **Explicit decision:** authenticated approve/deny POST uses existing `bean.security.checkOriginExact(...)` with trusted configured origin input and a winning pending transition. Its dev/loopback exceptions are not strict production origin proof; stock CSRF-token enforcement is disabled and must not be claimed. OAuth `state` is callback correlation, not authentication. Denial issues no code; only the mutation returns the AS-built registered callback for immediate browser navigation.
- **Protocol:** `/mcp/auth`, `/mcp/token`, RFC 8414 discovery and RFC 9728 path-specific resource metadata; preregistered public `none`/confidential `client_secret_basic` clients, code + PKCE S256, exact redirects and `mcp:read`. Token exchange requires the exact original `redirect_uri`. Reject malformed/duplicate parameters and bind client/redirect/resource/scope through redemption. No refresh, `offline_access`, dynamic registration, Client ID Metadata Documents, remembered consent or ordinary Cabloy JWT acceptance. `modules['mcp-auth']` owns an HTTPS-origin issuer and same-origin canonical `/mcp` resource → enabled instance, one unique mapping per host and exact host binding on every AS route; no cross-origin federation. Missing/inconsistent configuration fails closed, not Host/selector/token-derived authority.
- **One authority:** a tenant-scoped aggregate transitions `pending → codeReady → tokenActive`, with terminal denial/revocation, immutable bindings, approving user/auth identities and credential digests only. Defaults: pending **600s**, code **60s**, token **900s**; TTLs use seconds, `expiresAt` epoch milliseconds. Ordinary indexes, no authority caches, finite expired-row cleanup. Complete scoped `builderSelect().where(...).update(...)` predicates require numeric affected count **1**; cached `Model.update()` is not winner proof. Consume code/install token digest in one conditional UPDATE; reject ambient transactions or own and await commit before release. No automatic issuance retry, lost-response recovery or terminal revival.
- **Protected resource:** accept exactly one raw-header Bearer credential, never query/cookie/proxy credentials; SSR cookies remain supported. Fresh current lookup checks expiry/revocation/configuration/account validity in the trusted instance. Reload user/auth/roles and validate association/activity/activation in a fresh ordinary executor context; install server-owned Passport. Retain `performAction(..., { innerAccess: false })`, local RBAC, ownership and data scope. Missing/invalid bearer is 401 with applicable challenge; insufficient scope is 403; lookup/configuration failure denies before SDK/business dispatch. Standalone local fixture remains anonymous and credential-rejecting.
- **SSR/privacy:** static unnamed consent route, `requiresAuth: true`, `ssrProfile: 'session'`, empty layout. Model-owned summary state keyed by request disables persistence/dehydration; defer private client queries behind hydration/admission and preserve neutral initial HTML. Generate consumers from backend DTO truth. No raw credential, callback response or Authorization/cookie value in query persistence, SSR or logs. Protocol JSON is bounded, direct and `no-store`.

## Superseded apparatus and retained limits

Do not implement or relocate the unimplemented existing-`a-auth` aggregate/installation-marker schema, conditional keep-v1/fresh-only adoption package, external receipts, native physical-identity/connection qualification, activation epochs/fleet controls, qualified interval clock/restart continuity, correlation holder/bridge/bootstrap or cross-worker session-incarnation/first-binding synchronization apparatus.

Use ordinary application wall-clock deadlines assuming a correctly maintained host clock, not a qualified nonrollback/fleet-coherent time guarantee. Expiry, fail-closed current lookup, one-use state and commit-before-release remain mandatory. SQLite on Vona's primary datasource is the first verification target; no cross-dialect/worker/host, clone/rollback or production qualification follows. Browser logout retains existing framework behavior, not a new synchronous issued-token revocation guarantee.

## Finite exit and evidence

Require connected login/return → approve/deny → code/S256 exchange → real Bearer MCP call; critical redirect/client/resource/scope, unauthenticated/cross-origin decision, expiry/revocation/account and replay negatives; separate `mockCtx(...)` competitors with durable winner assertions and precise persisted cleanup; standalone/transport/drain regressions; generated contracts, paired affected SSR/REST builds and reverse dependency sync; a few integrated-SSR browser/hydration scenarios; and public docs build after concurrent scaffolding. These are prospective here, not passing results or legacy/full ATP closure.

Stop optional refinement after the approved outcome and required checks. No environment operation, reset, shared-port change, process killing, deployment or commit follows. Production registry, management UI, refresh, remembered consent and stronger deployment guarantees remain separate scope.
