## Implemented supported class and proof distinctions

The opt-in, unregistered foundation owns completed application/instance lifecycle separately from legacy flags, opaque attempt/publication/capability identities, detached coherent config, a fresh registry read/recheck port and early immutable context pinning. It refuses unsupported config, stale/forged/foreign capability, conflicting options, expired or changed publication and ordinary nested rebinding before DB work. It never registers, starts, reloads or repairs an instance at admission.

Configuration supports finite scalar/plain-record/array own-data values. Accessors/cycles/exotic leaves refuse without getter evaluation. Function leaves need an exact provisioning-time allowlist and frozen own data; immutable closure behavior remains a trusted assumption, not something freezing proves. There is no default production allowlist or provisioner. Exact persisted text/NULL travels with detached effective merged configuration; semantic JSON equality is insufficient.

The setup class uses an explicitly provisioned static route and already-owned inert handle. Existing database ALS and fresh independent transaction state are reused; this is not a native transaction or driver qualification. There is no request-time `getDb`/`getClient`/connection acquisition, ambient fallback or caller `dbInfo`. The provider is implementation-file-only and unregistered. Private issuance/provisioning is not exported in the public barrel; canonical URL fixture imports share module identity, and private collaborators are explicitly injected. Public production imports use `vona`, without compiler-config/subpath workarounds.

Pure core and real Start execution use local controlled collaborators, not a second application. Admission tests use inert ports; executor healthy tests reuse actual runner-owned context/ALS/disposal with local facades, separately from controlled failure ports. Checkpoints do not prove atomic revocation, cancellation, fleet fencing, native SQL safety, complete ABA detection or protected nested business dispatch. The SQLite profile remains independently scoped and unchanged by this increment.
