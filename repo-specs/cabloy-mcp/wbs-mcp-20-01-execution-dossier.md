## 4. Selected candidate — bounded design accepted, execution not authorized

Qualify the accepted modern-only adapter over **real Node HTTP + Vona executor/ALS/handleRequest/raw router**, with synthetic request-scoped JSON/SSE and lifetime fixtures. Do not register a production controller, add another app, or implement business dispatch. This provides integration value beyond an empty adapter while leaving the full production chain unqualified.

### Concrete composition

1. Use one dedicated root-managed single-file invocation and the existing Vona singleton app. No proven per-test fully started app factory exists; another `VonaApplication` changes the global app resource pointer.
2. Command-local `SERVER_LISTEN_DISABLE=true`; require effective disablement, test/managed identity, **no `app.server`**, and no pre-existing target routes. Fail rather than modifying config or taking over a busy resource.
3. Serial suite owns dynamic raw POST/GET/DELETE `//mcp` registrations and a test-owned `127.0.0.1:0` listener. Derive exact local Host/Origin from its allocated address; enforce ADR 0004's direct-only admission **before executor**, plus private request-object membership checked by handlers.
4. Explicit `instanceName: null`, literal `innerAccess: false`, native `req/res`, no inherited Passport/state or transaction; no per-request database switch. Invoke real Koa `handleRequest` and `SymbolRouterMiddleware`, not the full `app.middleware` chain. No tenant/business beans or `performAction` calls.
5. Install the per-request pure Node native writer/error boundary before `handleRequest`; contain rejection of the whole executor promise. Use one bounded body reader and the selected adapter's verified pre-parsed-body path. Await adapter, owned tasks and transport cleanup, then executor/disposal, before exactly-once capacity release.
6. In `finally`, close admission, drain/cancel and await owned work, close owned sockets/listener/timers, unregister only owned routes. Managed runner owns app/resource shutdown. Uncooperative work fails the run; it does not become detached successful cancellation.

The direct-only policy rejects forwarding, credentials, selectors, query/alternate targets, method overrides and ambiguous framing. Invalid present Origin stays `403`; explicit GET/DELETE are `405`. Exact accepted fixture status/precedence belongs to ADR 0004. Null is a test-only no-instance branch, not production tenant admission or an authorized default instance.

### Source-backed feasibility and proof limits

- [Router register/unRegister](../../vona/src/suite-vendor/a-vona/modules/a-web/src/bean/bean.router.ts) and [web main](../../vona/src/suite-vendor/a-vona/modules/a-web/src/main.ts) share the per-app router. Raw registration bypasses controller ContextRoute/guards/interceptors/pipes/Aspect. It can exercise path-helper/raw lookup, **not** decorated controller registration or parser/envelope override correctness.
- [Executor](../../vona/src/suite-vendor/a-vona/modules/a-executor/src/bean/bean.executor.ts) resolves instance before the `handleRequest` callback; middleware-first admission is too late. Null skips instance lookup, but is incompatible with the ordinary instance middleware; the reduced chain is intentional.
- [Production listen startup](../../vona/src/suite-vendor/a-vona/modules/a-web/src/bean/startup.listen.ts) and [ALS](../../vona/packages-vona/vona-core/src/lib/core/asyncLocalStorage.ts) expose genuine native/context/disposal anchors. Default listener has no whole-executor outer catch; a disposer failure can skip subsequent disposal and counter decrement. The harness contains rejection, not repairs those framework gaps.
- [Managed runner](../../scripts/runIsolatedTest.ts) inherits the listener-disable flag and forwards the selector; [test CLI](../../vona/packages-cli/cli-set-api/src/lib/bean/cli.bin.test.ts) accepts `src/...`. [Test bootstrap](../../vona/packages-cli/cli-set-api/toolsIsolate/test.ts) starts the singleton and appends the standard runner completion file. Thus “single-file” means one selected module test plus runner infrastructure, not a second app or no app startup.

No full system middleware, production controller, Host/instance/OAuth admission, ordinary-route regression, domain cancellation/rollback, deployment quota or protected-audit guarantee is proved by this candidate. The accepted production route and full ATP retain all of those applicable obligations.

### Observed request, system and controller ordering

The actual original listener returns the promise from:

```text
native req/res
  → executor.newCtx({ dbInfo: { level: 0 }, innerAccess: false, req, res })
```

### Proposed API and invariant contract

All following API names are **new proposed additions**, not currently runnable/exported APIs.

```ts
export type RequestBoundaryFailure =
  'observer_failed' | 'diagnostic_failed' | 'late_callback_failed';
export type VonaScopeOutcome = 'not_created' | 'disposed' | 'dispose_failed';
export type VonaScopeOutcomeObserver = (outcome: VonaScopeOutcome) => void;

// RequestBoundary is opaque: private issuer identity, not a structural options bag.
export function createRequestBoundary(options?: {
  readonly onFailure?: (failure: RequestBoundaryFailure) => void;
}): RequestBoundary;
export function runWithRequestBoundary<T>(boundary: RequestBoundary, continuation: () => T): T;
export function getRequestBoundary(): RequestBoundary | undefined;
export function captureRequestBoundary(): RequestBoundaryCapture | undefined;

export interface RequestBoundaryCapture {
  readonly diagnostics: 'suppress';
  reportFailure(failure: RequestBoundaryFailure): void;
  snapshot(): Readonly<{ portFault: boolean }>;
}

// New method on VonaAsyncLocalStorage, alongside the unchanged run overloads:
// runObserved<R>(store: VonaContext, callback: () => R,
//   observer: VonaScopeOutcomeObserver): Promise<R>;

export interface INewCtxLifecycle {
  initializeContext?: (ctx: VonaContext) => void;
  onScopeOutcome?: VonaScopeOutcomeObserver;
}
// Third trusted argument on executor.newCtx / mockCtx / newCtxIsolate:
// lifecycle?: INewCtxLifecycle

// Factory-owned logger helpers, exported by the existing logger barrel:
// createDiagnosticLogger(raw: Winston.Logger): Winston.Logger;
// getSuppressedDiagnosticLogger(): Winston.Logger;

// Module-internal telemetry helper surface, no metadata/barrel registration:
// recordSpanException(span: Span, error: unknown, capture?: RequestBoundaryCapture): void;
// endHttpSpan(span: Span, statusCode: number, aborted?: boolean): void;
// createHttpSpanEnd(span: Span, response: HttpSpanResponse,
//   capture?: RequestBoundaryCapture): Readonly<{ finish(): void; close(): void }>;
// HttpSpanResponse is a minimal structural native-response port:
// statusCode, writableEnded, and counterpart listener removal, never ctx/service.
```

1. **Capability and propagation.** Fixed `diagnostics: 'suppress'`; no severity/payload mode, context reference, user alias or arbitrary diagnostic event. Freeze the issuer-created token/capture; authenticate with private identity/WeakMap, not a public symbol/property. Private ALS makes the boundary active before provider/context/setup and through awaited/nested work. Same-token nesting joins; invalid/different-token nesting rejects with a fixed error before its continuation. There is no public clear/disable operation. `runWithRequestBoundary` preserves the continuation's synchronous return/throw and async Promise identity/settlement rather than always making it async. No headers/RPC/entity/extraData can mint or downgrade authority. These are trusted in-process APIs, not a sandbox against malicious application code.
2. **Pure ports.** Capture contains only fixed policy, bounded failure port and sticky boolean fault; no ctx, bean, scope, logger or ALS runner. Failure reporting is idempotent per fixed classification, synchronous/nonthrowing, suppresses recursive reentry and never forwards a raw Error. A throwing port latches `portFault`; it cannot replace the business result/error or recursively log itself. Missing boundary leaves ordinary behavior unchanged. Late users must capture while live; do not reacquire disposed scoped state.
3. **Early initialization.** Add the trusted third lifecycle argument, never an `INewCtxOptions`/`extraData` field. Forward it through `mockCtx` and `newCtxIsolate`. Enter the newly created context's ALS, then invoke synchronous, fallible `initializeContext(ctx)` **before** innerAccess, locale/timezone, delegation, instanceName setup, DB switching, instance lookup and callback/commit consumers. No thenable initializer is accepted as a substitute for a synchronous hook. An initializer throw follows ordinary executor rejection and actual disposal. No config pin, admission receipt, native writer or instance provider is installed by this increment.
4. **Owned outcomes.** `not_created` is emitted only when context creation did not return an object, not when setup later throws. Once a context exists, `runObserved` owns its actual disposal observation. Keep private per-owned-run identity, not context properties/extraData. Ordinary same-current-context `run` reentry joins and emits no second scope. Same-current `runObserved` rejects ownership misuse before callback, without fabricating `not_created` or `disposed`. Observer exceptions are swallowed, reported as `observer_failed` when a capture exists and cannot change caller settlement. `disposed` is reported only after actual awaited container disposal succeeds and normal owned cleanup completes; it is never inferred from callback/response/timer completion. Pending emits no successful terminal outcome. A counter/observer fault must not be relabeled successful cleanup.
5. **Preserve disposal failure.** Report `dispose_failed` only from actual disposal rejection; rethrow the identical rejection and preserve existing finally precedence, skipped decrement, remaining-disposer/map state and caller semantics. No retry, continue-disposer loop, aggregate-error replacement, counter repair or shared-app failing disposer. Controlled fake app/context/container/counter exercises the same ALS implementation, separately labeled; it is not a second `VonaApplication` or proof of real failure recovery.
6. **Before-Winston prevention.** A factory-owned facade gates `log`, seven severity methods, `write`, `child`, `startTimer`, `profile` and profiler `done` before passing arguments to raw Winston. Keep raw target private; preserve ordinary receiver, chaining, child metadata and profiler behavior. Guard handles acquired before entry. Protected-created children/timers retain no supplied metadata and remain inert after exit; ordinary cached handles remain usable afterward. Suppressed supported write callbacks complete once without payload/error. `profiler.logger` must not leak the target. BeanBase/AppLogger protected get/child returns inert handles before cache/config/transport/bean-name evaluation and never caches them. Do not modify an existing singleton, console, prototype or global logger.
7. **Defense at supported diagnostic sources.** Prepend format suppression before Axios/Error/context/splat/filter/lazy/JSON/color/console stages. Guard direct exported formatter entrypoints before info/options/useApp reads; move console callback destructuring behind the guard. HTTP and action AOP protected branches invoke `next()` directly before diagnostic ctx/options/receiver/args/result/error/serialization/profiler work. Preserve exact business return and rejection. This does not prevent eager argument evaluation performed by arbitrary caller code before invoking the guarded logger.
8. **Telemetry.** Protected middleware, global facade/service and inner-action branches avoid diagnostic scoped lookup, headers/method/name/options/Error evaluation and exporting. Return the existing nonrecording span or invoke the business continuation directly as appropriate. Move scoped-context default expressions behind the guard; a body guard alone cannot protect default arguments. Pure `recordSpanException` guards before Error inspection; pure `endHttpSpan` and `createHttpSpanEnd` are called by both production service/middleware paths. Capture only span, native response, capture and bounded scalar state. First terminal event wins, counterpart listeners removed, duplicate late callbacks nonthrowing; no ctx/scoped-service access after disposal. Infrastructure exporter/console failures remain an explicit excluded branch, not a universal sandbox claim.
